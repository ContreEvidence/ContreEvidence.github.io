# Politique de réouverture du corpus — contraintes, possibilités et preuves

Mise à jour : 15 août 2026

## Décision éditoriale

Tout contenu déjà publié est désormais **révisable sur le fond**, même s’il est exact, sourcé ou techniquement propre.

Le nouveau principe est :

> **Tout est à explorer tant que l’impossibilité n’est pas démontrée.**

Ce principe est immédiatement complété par :

> **Absence de preuve d’impossibilité ≠ preuve de faisabilité.**

Le site doit donc être plus difficile à convaincre qu’une voie est fermée **et** plus difficile à convaincre qu’une solution ingénieuse fonctionne.

## Audit initial du corpus

Premier passage automatique du 15 août 2026 :

- **15 P0** : fermetures fortes sans preuve ou périmètre suffisant détecté ;
- **46 P1** : affirmations fortes à vérifier ou resserrer ;
- **143 P2** : nécessités à examiner ;
- **576** formulations comportant déjà un signal de source ou de périmètre, sans que cela garantisse le fond.

Le rapport source est `reports/constraint-proof-audit.md`.

Ces nombres ne sont pas des erreurs comptables. Le filtre produit volontairement des faux positifs. Chaque signal doit faire l’objet d’une vraie relecture avant toute correction.

## Nouvelle règle de travail

### Pour une impossibilité

Avant d’écrire « impossible », « on ne peut pas », « obligatoire », « seul moyen », « aucune solution » :

1. identifier qui ou quoi impose la limite ;
2. produire la preuve ;
3. préciser le périmètre ;
4. vérifier si elle change avec le temps ;
5. tester un autre ordre des opérations ;
6. tester le fractionnement ;
7. tester un autre acteur ;
8. tester une combinaison de leviers.

Si le verrou n’est pas démontré, la conclusion devient **À TESTER**.

### Pour une solution

Avant d’écrire « on peut » ou de recommander un montage :

1. vérifier la légalité ;
2. vérifier la mécanique réelle ;
3. identifier les tiers qui doivent consentir ;
4. chiffrer le coût ;
5. tester le scénario défavorable ;
6. vérifier que la solution ne dépend ni d’une fausse déclaration ni d’une omission trompeuse ;
7. fixer le seuil d’abandon.

Une idée séduisante sans ces vérifications reste **À TESTER** ou **INCONNUE**.

## Le temps devient une variable obligatoire

Chaque dossier de décision doit chercher :

- ce qui est possible **avant** un changement de situation ;
- ce qui devient impossible **après** ;
- ce qui devient possible avec l’ancienneté ;
- ce qui change après remboursement d’une dette ;
- ce qui dépend d’une date réglementaire ou contractuelle ;
- l’ordre d’opérations qui préserve le plus d’options.

Une solution peut être une **fenêtre de calendrier**, pas seulement un produit, un droit ou un financement.

## Réécriture du corpus

Ordre de priorité :

1. P0 ayant une vraie incidence sur la décision du lecteur ;
2. P1 juridiques, financiers, professionnels ou immobiliers ;
3. dossiers à forte promesse où une réponse standard ferme prématurément l’espace des solutions ;
4. P2 lorsque le mot « doit » ou « il faut » cache une préférence plutôt qu’une nécessité.

À chaque réécriture, classer les pistes :

- VÉRIFIÉE ;
- CONDITIONNELLE ;
- À TESTER ;
- ÉLIMINÉE ;
- INCONNUE.

## Ce qui ne sera pas fait

- remplacer automatiquement « impossible » par « difficile » ;
- ajouter des exceptions imaginaires ;
- multiplier les options pour donner une impression de créativité ;
- transformer un exemple personnel en règle générale ;
- confondre contournement licite et fraude ;
- écrire qu’une voie fonctionne simplement parce qu’aucun texte ne l’interdit.

## Critère de réussite

Une page est meilleure lorsqu’elle distingue clairement :

1. ce qui est démontré comme fermé ;
2. ce qui est seulement difficile ;
3. ce qui dépend d’un acteur ;
4. ce qui dépend du calendrier ;
5. ce qui est techniquement ouvert mais encore à vérifier ;
6. ce qui est réellement faisable ;
7. le moment où il devient rationnel d’abandonner.

Le but n’est pas de promettre davantage. **Le but est de fermer moins de portes par paresse intellectuelle et d’ouvrir moins de fausses portes par enthousiasme.**
